Assessment date: 25 November 2026. Repository: [hemmingsenpeter-byte/biz-os](https://github.com/hemmingsenpeter-byte/biz-os).

This sprint prepares a reviewed receptionist shadow-pilot release. The core
platform is substantially built; the immediate work is to integrate existing draft
changes, close a local-model validation gap, and make shadow results easy to inspect.

## Owner work in parallel

These inputs are required for a meaningful live pilot and cannot be fabricated by
coding work:

1. Supply and confirm 100 historical HIVE enquiries using the existing private
   workflow in [RECEPTIONIST_EVAL.md](RECEPTIONIST_EVAL.md), retaining at least 50
   eligible held-out cases. Held-out details stay with the evaluator and owner.
2. Time 20 real owner tasks and count a normal week's enquiries. Check whether five
   hours saved per week is achievable; adjust target or scope if the baseline says
   otherwise. Supply HIVE's actual offer, voice and operating material.
3. Provide the Mac mini, installed local model and digest, Microsoft 365 tenant/mailbox
   configuration, business time zone and a real authentication-header sample. Resolve
   sender-verification behavior before any supervised sending decision.
4. Verify appliance installation, Tailscale access, restricted storage, off-box backup
   and restore, and operator health/alert review using the current deployment guide.
5. Run the local model on the owner-confirmed held-out cohort. The technical gate is
   at least 95% fully passing on at least 50 held-out cases. Follow this with two weeks
   of shadow operation with zero external actions, recording failures and model choice.

HIVE currently permits no private cloud evaluation. A cloud comparison depends on
the owner's separate explicit opt-in under the existing policy and CLI controls.
The sprint itself should not enable that opt-in or supervised dispatch.

correction → linked rule suggestion and regression case → candidate prompt/SOP

  closed, unmerged [PR #11](https://github.com/hemmingsenpeter-byte/biz-os/pull/11)
  rather than merging the old combined branch. This is the first stretch item if
  integration finishes early.

  paid-endpoint compatibility issue before enabling public signing.
- Keep live Xero/Twilio acceptance, estimator/bookkeeper activation, M7–M9 and
  second-business onboarding outside this receptionist sprint.

Stage 2 still requires demonstrated learning without older-case regression and five
hours saved per week for four consecutive weeks. A green release does not establish
either business outcome.
